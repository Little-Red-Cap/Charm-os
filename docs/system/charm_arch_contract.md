# Charm 架构契约（草案）

这是 Charm 长期架构的契约草案。目标是做到“硬核但克制”：强约束是默认，
但允许“被管理的例外”，以支持多处理器与多应用场景，同时保持确定性。

## 1) 默认强约束，例外可审计

默认规则必须严格。例外仅在满足以下条件时允许：
- 显式启用（配置开关），且
- 可观测（trace/统计可见）。

示例：
- 运行期创建默认关闭，但可在 PC/调试模式开启。
- ISR 语义默认强校验，但测试场景可放宽。

## 2) 核心语义平台无关

核心只定义语义：
- 调度、状态迁移、同步、超时。

平台差异属于：
- port（CPU/ABI、上下文切换、IRQ/tick），
- board（驱动与外设）。

核心不得内嵌平台假设。

## 3) 能力可裁剪，语义不可变

功能可以关闭（trace/debug/dynamic），但：
- 行为语义保持一致；
- 启用能力与否不影响“同输入同输出”。

确保 PC 与 MCU 行为一致。

## 4) 生命周期双阶段强制

系统必须区分：
- 注册期（启动），
- 激活期（运行）。

运行期创建是例外，而非常态。

## 5) 可观测性是一等公民

最低保证：
- trace 事件（环形缓冲），
- 调度统计（stats）。

可静默，但不可删除。

## 6) 可移植路线图明确

目标顺序固定：
1. Cortex-M 稳定性与确定性优先。
2. RISC-V 最小移植。
3. Cortex-A 在 core/port 边界验证后推进。
