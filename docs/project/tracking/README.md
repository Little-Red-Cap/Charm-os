# Tracking 入口

本目录只保留仍需维护的问题记录，不承担全仓任务管理或架构契约职责。

当前没有维护中的项目问题记录。新增 tracking 文件前必须写明 owner、当前证据、验收条件和退出方式；
已修复问题由源码、测试和 Git 历史追溯，不保留永久清单。

判断当前工作状态时，依次检查：

1. `git status --short` 与最近提交
2. 当前会话中的文件认领和明确计划
3. 对应模块的源码、测试与专题契约

历史 backlog、TODO 分工和 refactor ownership 见
[`project-guidance-and-tracking-v0`](../../archive/project-guidance-and-tracking-v0/README.md)；其中的优先级、
责任人、完成状态和文件路径均为历史快照。
