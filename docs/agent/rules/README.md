# Rules 导读

本目录存放 Charm 项目中 **长期稳定、跨任务生效** 的规则文件。

这些规则不是一次性 prompt，也不是某个单独技能的内部说明，而是 AI 在 Charm 项目中长期应遵守的协作与工程边界。

## 文件列表

### `collaboration.md`
定义 AI 与人协作时的行为预期、沟通方式与工作节奏。

适用：
- 需求不明确
- 设计存在多种方案
- 需要先讨论再实现
- 需要 review 或共同决策

不适用：
- 具体 API 约束判断
- Charm 模块依赖、IO、初始化、错误模型判断

### `embedded-modern-cpp.md`
定义 Charm 项目在现代 C++ 单片机场景下的技术立场与设计哲学。

适用：
- 判断设计是否符合现代嵌入式 C++ 方向
- 判断接口是否足够强类型、可验证、零成本抽象
- 判断是否错误回退到传统嵌入式写法

不适用：
- 具体项目模块依赖与装配细节
- 某个任务的步骤说明

### `charm-architecture.md`
定义 Charm 项目的具体架构要求、依赖纪律、错误模型、初始化与 IO 约束。

适用：
- 判断代码是否符合 Charm 项目要求
- 判断是否违反模块分层、IO 协议纪律、初始化纪律
- 判断时间源、输出、错误模型等是否一致

不适用：
- 纯协作方式讨论
- 抽象技术哲学辩论而不涉及 Charm 项目约束

## 读取建议

### 场景 1：任务描述不清、需要先对齐方式
先读：
1. `collaboration.md`

再根据任务补充：
2. `embedded-modern-cpp.md`
3. `charm-architecture.md`

### 场景 2：讨论 C++ 设计、接口、建模方式
先读：
1. `embedded-modern-cpp.md`

再补充：
2. `charm-architecture.md`

如任务涉及协作节奏，再补充：
3. `collaboration.md`

### 场景 3：代码评审、架构评审、实现合规性检查
先读：
1. `charm-architecture.md`
2. `embedded-modern-cpp.md`

必要时补充：
3. `collaboration.md`

## 总体原则

- 不要默认一次性加载全部规则
- 优先加载最相关的一层
- 当任务从“协作讨论”进入“代码实现/评审”时，再逐步补充更具体规则
- 规则的目标是帮助 AI 做出更一致的判断，而不是增加冗余输出
