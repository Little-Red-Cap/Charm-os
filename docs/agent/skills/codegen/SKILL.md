# codegen

用途：
- 用于 Charm 项目的代码生成、接口草拟、模块骨架设计与实现建议。
- 确保生成结果符合 Charm 协作方式、技术立场与架构纪律。

适用场景：
- 从零生成模块或接口
- 为现有模块补全实现骨架
- 将设计讨论落地为代码

不适用场景：
- 代替代码审查
- 代替项目 rules
- 在需求不清时直接跳过设计

依赖规则：
- `../../rules/collaboration.md`
- `../../rules/embedded-modern-cpp.md`
- `../../rules/charm-architecture.md`

相关文件：
- `../code-review/checklist.md`

---

## 1. 目标

生成的代码应：

- 符合 Charm 架构纪律
- 边界清晰、类型表达充分
- 可验证、可演进、成本清晰
- 不破坏既有约束

---

## 2. 默认理解

- Charm 不是通用 C++ 项目
- 不应套用通用工程模板
- 需求不清必须先讨论方案
- 建模优先于实现细节

---

## 3. 生成流程

### 3.1 先判断任务清晰度
- 若需求清晰 → 进入后续步骤
- 若存在关键歧义 → 先列方案、说明取舍，再生成

### 3.2 先建模再实现
- 明确 domain 是什么
- 明确核心类型是什么
- 明确边界在哪
- 明确由谁提供能力
- 明确哪些约束要写进类型

### 3.3 先生成“正确骨架”
- 接口语义正确
- 模块职责清晰
- 不破坏分层、初始化、错误模型、时间源

### 3.4 再补实现细节
- 逐步补足错误路径
- 参数检查
- 适配层
- TODO 标记真实未决点

---

## 4. 默认偏好

### 4.1 类型与接口
优先：
- 强类型
- 值语义句柄
- `std::span` / `std::array`
- `enum class`
- `concept` / `requires`
- `constexpr` / `consteval`
- 统一结果类型

避免：
- `void*`
- 裸指针做接口
- 依赖注释传递语义
- 依赖调用顺序传递语义

### 4.2 组织方式
- C++ Modules 优先
- 接口与实现组织清晰
- 语义组织优先于物理拆分

### 4.3 架构纪律
- 不破坏分层
- 不绕过 `init.graph`
- 不绕过 `io.registry`
- 不引入 busy-spin/阻塞等待
- 不引入非统一错误模型与时间源

---

## 5. 输出结构建议

- 设计说明（简要）
- 代码草案（结构清晰）
- 风险与未决点

---

## 6. 对“能用就行”的处理

若出现“能用但退化”的方案：

- 给出更符合项目目标的替代方案
- 说明为何保守方案不可取
- 若必须妥协，说明隔离与标记方案

---

## 7. 外部约束处理

若必须接入第三方 SDK/寄存器/legacy C 接口：

- 妥协限制在边界
- 适配层隔离
- 不污染核心模块
- 标注妥协原因

---

## 8. 与 rules 的关系

本技能只定义“如何生成代码”：

- 协作方式以 `collaboration.md` 为准
- 技术方向以 `embedded-modern-cpp.md` 为准
- 架构纪律以 `charm-architecture.md` 为准
