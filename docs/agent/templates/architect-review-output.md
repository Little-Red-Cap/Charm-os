# Architect Review Output Template

本模板用于 Charm 项目中的架构评审输出。  
目标是让架构评审不只是“说这个不太好”，而是能够：

- 先识别当前讨论的问题类型
- 说明为什么这是架构问题
- 明确关键判断依据
- 给出推荐落点和不推荐原因

相关文件：
- `../skills/architect-review/SKILL.md`
- `../skills/architect-review/examples.md`

# 模板

## 当前问题
<先说明当前讨论的是哪一类架构问题。>

可选类型：
- 能力归属
- 分层依赖
- 初始化装配
- IO 路径
- 错误模型
- 时间源
- 适配层边界
- 第三方依赖接入
- 系统演进方向

---

## 我的结论
<先给一句明确结论。>

可选表达：
- 我不建议这样做，因为它会破坏当前层次边界。
- 这个方向可以做，但当前落点不合适。
- 两个方案都能做，但我更推荐方案 B。
- 这不是局部实现问题，而是装配与能力归属问题。

## 推荐方案
<说明推荐的落点与组织方式。>

- 哪些边界必须保留
- 哪些能力必须隔离
- 哪些地方可允许有限妥协
