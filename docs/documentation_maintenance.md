# 文档维护约定

这份文档的目标不是增加一层新规范，而是减少文档继续发散的机会。

如果一个新同学需要在第一次进入仓库后的 10 到 15 分钟内回答下面几个问题，这套文档体系就算有效：

- 这个项目现在在守什么不变量
- 我当前任务应该先读哪几篇
- 哪些文档是现行约束，哪些只是阶段材料
- 代码、目标板、构建入口分别在哪里

## 维护目标

Charm 的文档维护默认追求三件事：

1. 可找到
   新读者能在少量入口文档里找到下一跳，而不是在同层级文档里随机漫游。
2. 可判断
   读者能快速判断一篇文档是“当前契约”还是“计划/复盘/草案”。
3. 可同步
   当行为、契约、工作流或构建入口变化时，相关文档能跟着一起更新。

## 文档层级

### 1. 入口层

职责：负责导航，不负责替代具体细节。

典型文件：

- 仓库根 `README.md`
- `docs/README.md`
- 各目录下的 `README.md`
- `*_overview.md`

要求：

- 说明这篇文档“负责什么”和“不负责什么”
- 给出下一跳，而不是试图把全部细节塞在一页里
- 同一主题尽量只保留一个主要入口

### 2. 契约层

职责：表达当前实现必须遵守的接口、边界、约束和不变量。

典型文件：

- `*_contract.md`

要求：

- 尽量与代码目录、模块边界、运行时行为一一对应
- 当接口、行为、依赖方向、启动方式发生变化时，应优先更新契约文档
- 不要把排期、愿景和未落地假设混进契约正文

### 3. 设计与阶段层

职责：记录方向、草案、阶段结论和过程性判断。

典型文件：

- `*_plan.md`
- `*_roadmap.md`
- `*_draft.md`
- `*_review.md`
- `*_summary.md`
- `*_v0.md`

要求：

- 开头应尽量说明这是“方向/快照/阶段材料”，不要伪装成长期稳定规范
- 如果已经有当前入口或契约，应在前文给出回链
- 阶段收口后，优先把真正稳定下来的内容回写到入口层或契约层

### 4. 推进与参考层

职责：服务推进、验收、对照和材料沉淀。

典型文件：

- `*_tasklist.md`
- `*_checklist.md`
- `reference/*`
- `generated/*`

要求：

- 这类文档默认不承担“新人入口”职责
- 如果它们依赖某个现行契约或总览，应在靠前位置显式链接
- 任务完成后，保留必要记录，但不要继续充当主题首页

## 命名与落点

新增文档前，先回答两个问题：

1. 这篇文档是入口、契约、阶段材料，还是推进材料？
2. 它应该挂在哪个主题目录下，才能让读者不用猜？

推荐约定：

- 需要导航时，用 `README.md` 或 `*_overview.md`
- 需要表达边界和现行规则时，用 `*_contract.md`
- 需要表达方向、设计或迁移时，用 `*_plan.md` / `*_roadmap.md` / `*_draft.md`
- 需要记录验收或推进状态时，用 `*_tasklist.md` / `*_checklist.md`

避免的情况：

- 同一主题出现多个“看起来都像首页”的文档
- 把一个 tasklist 写成对外长期说明
- 草案落地后不回写入口和契约，导致读者只能靠考古找当前事实

## 更新触发条件

出现下面这些变化时，应把文档更新视为同一项工作的一部分：

- 行为或接口契约变化
- 构建入口、preset、目录入口变化
- 公开工作流或协作方式变化
- 板级 handoff、启动方式、平台边界变化
- 某篇入口文档指向的下一跳已经失真

## 新增文档前的最小检查

在新建文档前，先检查：

1. 这个主题是否已经有入口文档
2. 是否已经存在内容高度重叠的草案或复盘
3. 新文档是否需要被 `docs/README.md`、目录 `README.md` 或根 `README.md` 路由到
4. 如果它会影响使用方式，是否需要同步更新相关契约

## 清理旧文档时的优先级

第一优先级：

- 修入口
- 修坏链接
- 修已经与当前代码/构建入口明显失真的描述

第二优先级：

- 收敛重复首页
- 把稳定事实从计划/复盘中回写到契约或总览

第三优先级：

- 整理历史材料
- 标注替代关系
- 把“仍有参考价值但不该继续当入口”的文档降级

## 历史参考与损坏文档

处理这两类文档时，优先目标不是“立刻修完”，而是“先降低误导性”。

- 第三方参考材料如果只剩历史来源或概念对照价值，应明确降级为“历史参考”，不要继续伪装成当前方案入口。
- 如果某条第三方结论已经被 Charm 自己的契约或总览吸收，可以继续收缩引用范围，必要时归档。
- 对暂时无法快速修复的损坏文档，入口层应明确标注“待恢复 / 不建议作为首选入口”，并给出替代阅读路径。
- 不要让编码损坏、内容失真或半恢复状态的文档继续出现在“推荐先读”的列表里。

## 建议的维护节奏

- 小改动：随代码或构建变更同步更新对应入口/契约
- 中等改动：在同一批改动中补目录级 `README.md` 或专题总览
- 大型重构：先调整入口层，再批量收敛契约和阶段材料，最后处理参考和历史沉淀

## 当前执行原则

在 Charm 仓库里，文档清理优先做“让人知道先看什么、什么最可信”，
而不是一开始就追求把所有旧材料都消灭掉。

先把入口和层级立住，后面的专题收敛才会越做越轻。
