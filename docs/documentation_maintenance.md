# 文档维护规则

本文约束仓库文档的入口、状态和清理方式，不定义产品或架构语义。

## 文档角色

| 角色 | 常用文件 | 负责 | 不负责 |
|---|---|---|---|
| 最高裁决 | 根目录 `CONSTITUTION.md` | Charm 身份与 Core 准入 | 实现细节、路线图 |
| 操作约定 | 根目录 `AGENTS.md` | Agent 路由与协作规则 | 架构裁决 |
| 入口 | `README.md`、`*_overview.md` | 说明范围并给出下一跳 | 复制专题正文 |
| 契约 | `*_contract.md` | 当前边界、不变量、失败语义 | 愿景、排期、复盘 |
| 探索 | `*_plan.md`、`*_roadmap.md`、`*_draft.md`、`*_review.md`、`*_v0.md` | 未冻结方案与阶段结论 | 充当默认入口 |
| 推进 | `*_tasklist.md`、`*_checklist.md` | 任务和验收状态 | 长期规范 |
| 参考 | `reference/`、`generated/`、`archive/` | 对照、生成物、历史追溯 | 当前事实与权威入口 |

文件名不授予权威。状态和上位裁决优先于 `contract`、`overview` 等后缀。

## 信任顺序

1. `CONSTITUTION.md`
2. `docs/architecture/charm_core_contract.md`
3. `AGENTS.md` 中的操作约定
4. 当前目录入口与现行契约
5. supporting 文档
6. exploration、推进、参考和归档材料

冲突时修正或降级低优先级文档，不在正文中并列多个答案。

## 写作规则

- 一篇文档只承担一种角色。
- 同一主题只保留一个默认入口。
- 开头直接写状态、范围和权威上位文档。
- 先写约束、接口、命令、路径和失败行为，再写必要背景。
- 删除愿景复述、情绪化判断、过程旁白和重复总结。
- 不用“强大、优雅、宏大、真正、显然”等词代替证据。
- 不用“我们将、未来可以、接下来考虑”污染现行契约。
- 示例必须支持一条明确规则；不能支持规则的示例应删除。
- 表格只用于比较固定字段，普通说明使用短段落或短列表。

## 状态要求

非 canonical 文档应在开头标明以下状态之一：

- `supporting`：局部有效，不定义 Charm Core。
- `exploration`：未冻结，不得作为实现依据。
- `archived`：只供追溯，不进入推荐路径。
- `damaged`：内容或编码不可信，并提供替代入口。

状态说明应在前 15 行内出现。

## 新增文档

新增前检查：

1. 是否已有入口或同主题文档。
2. 新内容能否直接补入现有契约或 README。
3. 文档角色和权威上位文档是否明确。
4. 是否需要同步代码、构建入口或测试命令。

不能回答以上问题时，不新增文件。

## 价值判断

未实施、未冻结或来自讨论的内容不等于垃圾。清理前检查它是否包含：

- 尚未进入契约的独立假设或反例；
- 可复用的技术证据、失败记录或比较结果；
- 被放弃方案的取舍理由；
- 仍未解决的问题和明确约束；
- 后续设计需要引用的术语来源。

存在以上任一内容时，优先压缩并标为 `exploration`，或移入 `archive/`。只有在内容已被更高权威文档完整吸收时，才删除原文。

以下内容可直接删除：

- 与现行文档重复且没有新增事实；
- 只有愿景、情绪和过程旁白；
- 引用失效且无法验证结论；
- 把未实施方案写成当前事实；
- 按对话步骤拆分、离开上下文后无法独立使用。

## 清理顺序

1. 修复或移除失真入口和坏链接。
2. 合并重复首页与重复背景说明。
3. 将已验证事实写回契约或入口。
4. 提炼有独立价值的讨论、取舍和未决问题。
5. 仅有追溯价值的内容移入 `archive/`；没有独立价值或可能误导的内容直接删除。

Git 历史用于追溯已删除的低价值中间稿，不能替代有价值讨论在当前树中的可发现性。

## 完成检查

- 本地 Markdown 链接有效。
- 推荐路径不指向 `archive/`、`reference/`、`generated/` 或已删除文件。
- 入口不复制专题正文。
- 契约不包含排期和愿景。
- exploration 文档有明确状态和上位入口。
- 删除文档后已更新所有直接引用。
- 改动保持 UTF-8，未引入新的编码损坏。
