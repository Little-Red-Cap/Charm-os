# Collaboration Rules

> **文档状态：`supporting`**

根 [`AGENTS.md`](../../../AGENTS.md) 负责语言、编码、提交和任务路由。本文件只补充仓库协作中的
决策升级、并行改动保护和证据沟通。

## 先建立事实

- 开始前确认真实仓库、目标文件、当前分支和相关脏改动；
- 以 source、CMake、实际 target 和测试输出为事实，不把文档愿景当现状；
- 明确区分已确认事实、工作假设、设计选择和未验证风险；
- 需求清楚时直接推进实现与验证，不用重复复述计划代替工作。

## 何时需要确认

只有以下情况需要暂停并让用户选择：

- 多条方案会改变公共接口、数据格式、兼容性或长期所有权；
- 操作具有不可逆风险，或会覆盖用户/并行任务的改动；
- 当前事实互相冲突，无法在源码和运行证据中裁决；
- 缺少外部凭据、硬件状态或产品决策，继续会产生伪实现。

普通实现细节、可逆局部选择和已有模式延续由 Agent 自行判断。提问应给出少量互斥选项、影响和推荐项，
不把开放式调查工作推给用户。

## 并行工作区

- 不修改、暂存、提交或回退与任务无关的脏文件；
- 目标文件出现并行变化时重新读取并合并意图，不能用旧快照覆盖；
- 只暂存本批文件，提交前检查 staged diff；
- 构建目录和设备可能被其它任务占用，删除、烧录或重启前先确认现场；
- 逻辑独立的改动分批提交，未验证的探索不混入已闭环提交。

## 沟通与验证

- 中间更新只报告正在核对的事实、发现的变化和下一步动作；
- Review 先列具体缺陷、风险和文件位置，再给摘要；
- 完成说明必须列出实际执行的验证以及未执行部分；
- 测试、schema、build-only、QEMU 和真实板证据按各自覆盖范围表述，不扩大结论；
- 遇到失败先保留日志和现场，说明失败阶段，不用模糊措辞掩盖。
