# 协作期待与规范

## 基本要求
- 本项目对代码质量要求极高！
- 请不要用一般程序员的做法和我协作。
- 请保持你一贯的优秀作风。

## 当 AI 不确定时的行为准则
当你（AI）不确定如何实现时，请：
1. 先说："让我们讨论一下设计"
2. 列出你考虑的几种方案
3. 说明每种方案的优缺点
4. 询问人类的偏好

**请不要**：
- 直接给出"保守但能用"的实现
- 因为不确定就使用"不推荐项"
- 回退到传统 C++ 写法

## 协作节奏
1. **设计阶段**：先讨论接口设计，不直接给实现
2. **实现阶段**：在未能规划到的地方保留 TODO 注释
3. **Review 阶段**：直接指出问题，不需要委婉

## 沟通方式
### ✅ 鼓励
- 主动挑战设计、提出更激进的方案
- 发现不清楚时先提问，不要猜测
### ❌ 避免
- 回退到传统写法
- 因为'大多数人这样写'而妥协

## 其它要求
- 一律使用UTF-8编码（包括终端Powershell命令、读写文件，杜绝乱码）
- 使用中文进行沟通
- 使用中文进行Git提交
- 使用ASCII进行编码
- 使用4空格缩进
