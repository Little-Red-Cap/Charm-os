# Vivid P0 任务拆分与排期（草案）

> 目标：先把“可用性/稳定性”做到可持续演进的基线。

## 0. 范围与原则

- 仅覆盖 P0（稳定与可用性）
- 不引入动态内存
- 保持接口兼容，优先“替换使用”而非“删除旧实现”

## 1. 任务拆分（P0）

### T0 字体流水线：默认 4bpp

**目标**：形成稳定的 4bpp 字体生成与接入规范  
**工作项**：
- 统一生成参数（bpp=4、范围、fallback 规则）
- 产出基础字体模块（Small/Normal/Large）
- 更新 `typography.cppm` 的默认字体映射

**产出**：
- 4bpp 字体模块（cppm）
- 字体生成脚本参数说明

**最小回归**：
- 编译通过
- 文本控件正常显示且无明显锯齿

---

### T1 事件一致性：禁用态/捕获/拖拽

**目标**：控件在禁用态不响应事件，拖拽/捕获路径不吞掉外层事件  
**工作项**：
- 全控件 `on_event` 统一检查 `is_enabled()`
- 拖拽结束事件仅在拖拽中消费
- overlay 与 focus 的边界补充测试场景

**产出**：
- 控件事件一致性修复
- 简单事件回归示例

**最小回归**：
- 编译通过
- 交互回归：点击/拖拽/滚轮/键盘路径可用

---

### T2 渲染正确性：滚动与布局边界

**目标**：滚动、布局在边界情况下不出错  
**工作项**：
- ScrollContainer 超过子节点上限的行为明确化
- hit_test 与渲染阶段滚动推进隔离
- 负尺寸/裁剪边界保护

**产出**：
- 滚动稳定性修复
- 布局边界检查

**最小回归**：
- 编译通过
- 滚动容器在边界情况下无抖动/错位

## 2. 排期建议（可调）

- 第 1 周：T0 字体流水线  
- 第 2 周：T1 事件一致性  
- 第 3 周：T2 渲染正确性  

## 3. 风险与依赖

- 字体生成依赖字体文件与生成参数一致性  
- 事件一致性修改可能引发控件交互边界变化  

## 4. 交付标准

- 编译通过  
- 基础交互可用  
- 文本显示清晰（4bpp）
