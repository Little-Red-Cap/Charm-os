
# 项目规范（临时约定，持续补充）

## 1) 格式化/日志/输出

- std::printf/sprintf/snprintf -> out::format 或 out::printf
- printf/puts/fprintf -> out::raw / out::write / out::logger
- 统一在非实时路径做格式化，实时路径只做简单写入

## 2) 容器与内存

- 动态容器优先替换为 core/service 固定容量容器
- 禁止在内核热路径中使用隐式分配（new/std::string/std::vector）
- 固定容量池/队列统一走 core/service 实现

## 3) 模块依赖

- Foundation（core/util、core/service、out）只能被上层依赖，禁止反向
- Domain 只能依赖 Runtime 与 Foundation，不依赖平台实现细节
- 新模块必须在 charm.* 聚合模块中显式导出

## 4) 字符串/编码

- 对外接口默认 UTF-8，内部按字节处理
- FAT LFN/UTF-16 转换放在 fs 层，不下沉到 core

## 5) 文件系统与 IO

- close()/flush() 必须走统一回收路径
- 只读打开不允许隐式创建文件
- Block/MAL/FS 的错误码向上透传，不吞掉

## 6) 代码风格

- 复杂逻辑块前允许少量注释，但禁止“显而易见”的注释
- 尽量保持 ASCII；非 ASCII 仅在文档或确有需求时使用

## 7) CMake 与第三方

- 第三方依赖优先 find_package，其次本地路径，最后 FetchContent
- 避免在核心模块中引入“必须联网才能构建”的依赖
